# Stage 8 - Build, Buy and Partner Analysis

**Status:** READY FOR G2 REVIEW

| Dimension | Build O3 capstone | Buy/configure platform | Partner/integrate |
|---|---|---|---|
| Synthetic academic objective | Strong fit | Weak-to-medium | Medium |
| Domain-control transparency | High | Unknown until diligence | Shared/variable |
| Speed within supplied repo | High | Procurement/setup dependency | Coordination dependency |
| Evidence traceability | Designed directly | Must be verified | Must be contracted and verified |
| Data/privacy exposure | Local by default | External by default unless special deployment | Depends on partner model |
| Vendor lock-in | Low through ports/adapters | High | Medium-high |
| Production readiness | Not claimed | Potential, not demonstrated | Potential, not demonstrated |
| Current cost confidence | Engineering units measurable | No quotes/terms | No statement of work |

## Decision

Build the local academic O3 POC. This decision is not a recommendation to build the real enterprise platform. A production decision requires a dated build-buy-partner exercise covering regulated-use support, data location, quality agreements, integrations, security, accessibility, exit/data export, supplier continuity and total cost.

## What remains reusable

Domain rules, events, schemas, evaluation cases, adapters and evidence contracts are portable assets. Provider-specific APIs, prompts or UI conveniences must not become the source of business authority.
